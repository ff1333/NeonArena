## 完整照读口播稿

下面七段就是最终口播。正常、清楚地朗读，段落之间停顿半秒，成片约 85 到 90 秒。括号中的内容是录制提示，不要念出来。

### 00-08 秒：项目介绍

（画面：开始界面，点击开始后快速展示初始武器三选一并选中一种）

> 大家好，这是我用 Unity 六和 C Sharp 完成的二维生存射击项目，霓虹竞技场，英文名 Neon Arena。

### 08-21 秒：核心玩法

（画面：玩家移动、自动射击、击杀敌人并拾取经验）

> 开局先从三种武器中选择一把。玩家移动躲避敌人，武器自动索敌射击，并通过三选一升级决定成长路线。

### 21-35 秒：武器和升级

（画面：升级三选一，选择升级后切回战斗；展示不同颜色的武器和子弹）

> 项目有手枪、冲锋枪和激光枪，伤害、射速和射程不同。最多装备六把，每把武器独立冷却和索敌。

### 35-48 秒：敌人与战斗反馈

（画面：普通追击敌人、冲刺敌人或狂暴敌人，以及出生预警、命中闪烁和粒子反馈）

> 敌人有追击、冲刺和狂暴三种行为，按时间解锁。出生预警、命中、死亡和升级都有反馈。

### 48-62 秒：对象池优化

（画面：Unity 的四个对象池，再切到两张 Profiler 记录）

> 工程上，我用对象池复用子弹、敌人、经验物和出生预警，结束后重置并回收，Profiler 记录了优化过程。

### 62-75 秒：数据与代码结构

（画面：`Assets/Data`，再展示 `PlayerShooter`、`TargetSelector` 和 `EnemySpawner`）

> 我用 Scriptable Object 管理武器、敌人和升级数据。射击系统通过注册表筛选射程内目标，在最近的一圈中优先攻击生命值最低的敌人。

### 75-90 秒：测试、平台和结尾

（画面：Windows、WebGL、Android 构建或 GitHub README、开发日志和 Release 页面）

> 项目通过十分钟发布候选测试，已构建 Windows、Web G L 和安卓版本，安卓端支持全屏浮动摇杆。源码、日志、测试证据和正式包都在 GitHub。谢谢观看。

## 英文读法

- `Unity`：读作“优尼提”。

## 朗读和剪辑方法

1. 先不录音，完整读两遍；只要表达自然，不需要模仿播音腔。
2. 正式录音时一段一段录。某段读错，只重录这一段，不必从头开始。
3. 每段开头和结尾保留约一秒安静时间，剪辑时更容易拼接。
4. 画面比口播提前约半秒切换，让观众先看到再听到说明。
5. 如果超过 90 秒，优先删除英文项目名和最后的“谢谢观看”，不要加快到听不清。
6. 如果不足 75 秒，放慢语速并增加段落停顿，不要临时添加未经验证的功能。

## 录制要求

1. 使用最终 `main` 对应的正式包，不用参考工程或临时测试数值。
2. 游戏片段必须真实操作，不能用静态图片冒充运行。
3. Profiler 画面只说“完成对象池实现和代表帧记录”，不说未经证据支持的提升百分比。
4. 录制前关闭聊天、通知和包含隐私信息的窗口。
5. 导出为 1080p、H.264、MP4；完整播放一遍后再上传。
6. 不愿录口播时可以只用表格中的短字幕，但成片仍要保留真实游戏声音或稳定的低音量背景音。

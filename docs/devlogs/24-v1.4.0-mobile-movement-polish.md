# v1.4.0 移动端移动手感收尾

日期：2026-10-31

## 问题

Android 试玩时，玩家虽然能够正常移动，但连续推摇杆会感觉位移一格一格、不够顺滑。问题不在移动速度，而在完整的输入到显示链路：

- 玩家只在 `FixedUpdate` 中以固定物理步移动；
- `Rigidbody2D` 原来没有启用插值；
- 相机在每个渲染帧读取玩家位置，容易放大物理帧之间的阶梯感；
- 浮动摇杆的小幅触控噪声会直接成为移动输入；
- Android 没有明确指定目标帧率。

## 修改

1. `PlayerMovement.Awake` 强制将刚体插值设为 `RigidbodyInterpolation2D.Interpolate`，场景序列化值同步修改。
2. 摇杆输入增加 `0.08` 死区，并把死区以外的幅度重新映射到 `0-1`，不会损失满幅速度。
3. 使用 `Vector2.MoveTowards` 做轻量响应：加速 `14/s`、减速 `22/s`。松手比起步更快，避免惯性拖沓。
4. 仍在 `FixedUpdate` 通过 `Rigidbody2D.MovePosition` 移动，保留碰撞和竞技场边界规则。
5. Android 运行时目标帧率设为 `60`。
6. 编辑器鼠标模拟字段使用条件编译隔离，关闭未使用的 Unity 云诊断，正式构建不再产生相关警告。

## 为什么不是直接提高速度

提高 `moveSpeed` 只会让每个物理步跨得更远，阶梯感反而可能更明显。插值解决渲染帧之间的位置连续性，死区解决触摸噪声，短促加减速解决方向变化的生硬感，这三项才对应实际症状。

## 面试讲法

> 移动卡顿不是单一速度参数问题。项目原来在 50 Hz 物理帧移动，但刚体没有插值，相机又按渲染帧跟随，所以高刷新率设备会看到阶梯位移。我开启 Rigidbody2D 插值，在输入层增加重映射死区，再用短时加速和更快减速平滑方向变化，同时保持 MovePosition、碰撞和边界逻辑不变。最后用 PlayMode 测试锁定插值和输入边界，并重新构建 Windows、Android 零警告包。

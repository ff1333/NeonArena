# v1.4.0 智能首领与动态战斗导演

日期：2026-10-27  
分支：`feature/intelligent-combat-ai`  
基线：`v1.3.0` / `517dd0e`

## 1. 本轮需求

v1.3.0 的完整流程已经稳定，但两个系统仍然“看起来像程序”：

- Boss 用 `attackIndex % 3` 固定轮播弹幕、区域攻击和冲刺；
- 普通刷怪只按存活时间缩短间隔，难度不读取玩家状态。

v1.4 的目标不是增加更多普通武器，而是完成可感受、可验证、可解释的运行时玩法 AI：

1. 六个 Boss 行为可独立评分、执行和冷却；
2. Boss 根据玩家距离、速度、靠边程度、自身血量和重复历史选择行为；
3. 动态战斗导演只能调整刷怪间隔、批次、上限和权重，不能无限加压；
4. 残血且刚受重伤时出现有限恢复窗口；
5. 开发模式能看见决策，自动测试覆盖边界；
6. 不破坏六武器、小首领、金色奖励、最终首领和胜利闭环。

### 2.2 Boss 固定顺序

`BossAgent` 每 `attackIndex % 3` 选择：

| 余数 | 行为 | 主要参数 |
|---:|---|---|
| 0 | 扇形弹幕 | 小首领 3 发 / 最终 7 发；18/28 伤害 |
| 1 | 区域轰炸 | 小首领 1 个 / 最终 3 个；25/38 伤害 |
| 2 | 冲刺 | 锁定方向，速度 11/15，持续 0.55 秒 |

决策间隔小首领 1.1 秒、最终 0.75 秒；前摇 1.05/0.85 秒，最终半血缩短到 0.65 秒。普通移动速度 2.3/3.4，半血只影响前摇和弹幕追加，不改变技能顺序。

## 3. Boss Utility AI

### 3.1 结构

```text
BossSituation
→ BossUtilityBrain
   ├─ 冷却过滤
   ├─ 半血门槛
   ├─ 距离偏好
   ├─ 玩家速度/靠边修正
   ├─ 重复惩罚
   └─ 最高分选择
→ BossAgent 执行
   ├─ 移动
   ├─ 瞄准线/环形预警
   └─ BossHazard 对象池
```

`BossBehavior` 管评分接口、冷却、前摇缩放和生命周期；六个子类只描述自己的评分倾向与执行节奏。`BossAgent` 不再知道“第几个技能”，只负责把情境交给决策器，再把选中行为跑完。

### 3.2 六个行为

| 行为 | 分数提高条件 | 执行 |
|---|---|---|
| 追击 | 距离越远越高 | 短时间高速接近 |
| 预测冲刺 | 中距离、玩家速度较高 | 锁定预测点，预警后冲刺 |
| 扇形弹幕 | 中距离、玩家速度较低 | 预警线后扇形发射 |
| 区域轰炸 | 玩家靠边、低速 | 延迟范围危险；最终追加两侧 |
| 环形弹幕 | Boss ≤ 50% 生命，近距离 | 环形弹幕，最终弹量更高 |
| 重新站位 | 玩家贴脸、Boss 靠边 | 向侧后方换位 |

### 3.3 可复现性

- 决策不使用随机数；
- 平局按行为注册顺序处理；
- 冷却在行为开始时记录；
- 重复惩罚按连续次数递增，但有上限；
- 相同情境、冷却和配置产生相同选择。

### 3.4 配置资源

`Assets/Resources/Combat/BossDecisionConfig.asset` 保存：

- 六条行为的基础权重、距离区间、冷却、前摇、恢复；
- 重复惩罚 2.4、最大 4.8、记忆 6 秒；
- 最终半血前摇缩放 0.75。

没有挂资源时使用 `BossDecisionConfig.CreateDefault()`，避免场景升级后 Boss 直接失去行为。

## 4. 有边界的动态战斗导演

### 4.1 输入

- 玩家生命比例；
- 最近 3 秒实际受伤比例；
- 最近 8 秒击杀速率；
- 武器数量；
- 场上存活敌人数；
- 当前敌人上限。

`Health.Damaged` 只报告护甲结算后的实际伤害，避免把被抵挡的伤害计入压力。

### 4.2 压力与输出

```text
desired =
  base 0.25
  + health 0.55
  + weapons 0.18
  + killRate 0.22
  − crowd 0.20
  − recentDamage 0.35
```

压力平滑到目标后夹在 `[0,1]`，输出：

| 输出 | 范围 |
|---|---|
| 刷怪间隔 | 0.55–1.50 秒 |
| 敌人上限 | 10–28 |
| 单批数量 | 1–3 |
| 难度等级 | 0–4 |
| 高级敌人权重 | 随压力提高，恢复时降低 |

### 4.3 恢复窗口

```text
health ≤ 0.35
AND recent 3s damage ≥ 0.18
AND recovery cooldown elapsed
→ suppress new spawns for 3.5s
→ no retrigger for 7s
```

恢复只停止新增刷怪；已经存在的敌人和已经落地的出生预警不消失。导演不修改玩家伤害、敌人伤害或生命规则，因此不存在“暗中改数值制造智能”。

### 4.4 与刷怪器的边界

`EnemySpawner` 仍负责位置、预警和对象池。它只从导演读取：

- `SpawnInterval`
- `BatchCount`
- `EnemyCap`
- `SpawnsSuppressed`
- `EnemyWeightMultiplier`

`ClampBatchToCapacity` 在每次生成前检查剩余容量；达到上限时本批为 0，而不是先生成再删。

## 5. 调试与测试

### 5.1 开发面板

`CombatDebugOverlay` 在 Editor / Development Build 自动创建：

- 当前行为、上一次行为、Boss 生命；
- 前四名候选分数、冷却、重复标记；
- 压力、难度等级、实际间隔、上限、批次；
- 最近伤害、恢复倒计时、存活敌人数；
- `F3` 切换。

面板只读，不改变决策和数值。

### 5.2 自动测试

最终 PlayMode：

```text
18/18 passed
Duration 38.74s
```

新增覆盖：

- 六个行为独立启动并完成；
- Boss 死亡停止决策、释放全部危险对象；
- 冷却中的行为不可选；
- 重复行为扣分且不再连续选择；
- 远处玩家偏好追击；
- 靠边玩家显著提高区域轰炸分数；
- 半血前环形弹幕不可用、半血后可用；
- 压力、间隔、上限、批次不越界；
- 残血重伤进入恢复；
- 恢复冷却内不重复触发；
- 达到敌人上限后批次为 0；
- 实际场景中的导演在玩家重伤后进入恢复。

### 5.3 尚需人工验证

- Boss 权重和导演参数是否“好玩”；
- Windows 实际战斗可读性；
- Android 触屏下 `F3` 面板默认显示是否遮挡过多；
- 不同武器构筑下的恢复窗口频率；
- 小首领和最终首领半血阶段的躲避空间。

自动测试只能证明规则，不替代试玩。
